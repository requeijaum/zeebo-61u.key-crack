# Zeebo 61u.key Crack

Reverse-engineering the Zeebo console's diagnostic unlock key (61u.key) generation algorithm.

## Background

The Zeebo (MSM7201A-based console) requires a **61u.key** file on SD card (`fs:/card0/61u.key`) or internal NAND (`fs:/mcp/61u.key`) to enable the USB DIAG port. The key is:
- 14 alphanumeric characters (A-Za-z0-9), case-sensitive
- Generated by an internal TecToy tool from the console's IMEI (per TecToy insider reports; tool lost)
- Validated by Longcheer OEM code (`OEM_LCTSystemCtl.c` family) on ARM11/BREW side

## Key Findings (verified)

### Validation logic (APPS.bin 1.1.2, Ghidra decompiled)
- `check_61u_key @ 0x108d081c`: resolve mcp path → resolve card0 path →
  read both (heap `fileSize+1`, bounded) → **`strcmp(mcp_content,
  card0_content)`** → SUCCESS(0,6) → event gate (`0x97`/`0x10a`) →
  DIAG enable via AUXSETTINGS (vtable `+0x54`). Valid until reboot.
- **Fail-open**: missing internal key → SUCCESS path. Explains why the
  Hospital removes `mcp/61u.key` (permanent DIAG).
- No IMEI/serial/NV read, no crypto, no length/charset check. Keygen
  secret is TecToy-side only (provisioning code absent from firmware).
- ARM11-only: no modem/RPC involvement (`re/notes.md` §2e).

### Data (10 pairs + 3 unpaired keys + 2 unpaired IMEIs)
- Duplicate key `3ulp223EpFKhDT` for 2 IMEIs (possible spreadsheet error).
- Batch hypothesis falsified at available granularity.
- Key alphabet NON-uniform (uppercase bias, χ²-confirmed); 80-bit value
  uniform, bias lives in the encoding step. No timestamp/CRC structure.
- `61s.dat` = SIM PIN (4 digits), unrelated. Wiki mirrors in `docs/`.

### Closed avenues
zloader (sig bypass only), Z-Wheel (no key refs), modem EFS (NV only),
SMS remote injection (no modem-autonomous path), sibling MSM7201A
basebands (same SPC family), presence-only validation (dead: strcmp
exists), overflow via key file (bounded reads).

### Open avenues (need hardware or people)
AT write primitive: `+LCTUSBLOCK="<content>"` writes `fs:/mcp/61u.key`
(relative path ⇒ internal partition, `re/notes.md` §28) — if the AT channel
is reachable *without* DIAG, writing a chosen key to NAND plus the same value
on the SD defeats `strcmp(mcp, card0)` with no keygen. Blocking unknown: which
port carries the parser. Also open: EMAPPLET Memory Copy (no sig gate in copy
flow), Text Script auto-copy (DIAG-gated per wiki), DIAG fuzz pre-gate +
SPC defaults (`tools/diag_fuzz.py` ready), garbage-key confirm test
(`61u.key.bad`, predicts FAIL), JNE-crack (`04d1→00bf` at file
`0x80c864`, needs NAND write), EDL 9008 probe (top payoff if unfused),
more pairs/keys (Layo, Telegram), TecToy tool/DB leak, timing oracle
(impractical), UART pads, 1.1.x downgrade (no image).

See `re/notes.md` §16 for the ranked 14-vector attack surface map.
