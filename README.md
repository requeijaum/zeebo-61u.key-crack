# Zeebo 61u.key Crack

Reverse-engineering the Zeebo console's diagnostic unlock key (61u.key) generation algorithm.

## Background

The Zeebo (MSM7201A-based console) requires a **61u.key** file on SD card (`fs:/card0/61u.key`) or internal NAND (`fs:/mcp/61u.key`) to enable the USB DIAG port. The key is:
- 14 alphanumeric characters (A-Za-z0-9), case-sensitive
- Generated by an internal TecToy tool from the console's IMEI
- Validated by `OEM_LCTSystemCtl.c` (Longcheer system applet) on ARM11/BREW side

## Key Findings (So Far)

### Validation Logic (APPS.bin, Thumb function at `0x1078c8d0`)
- Checks `fs:/mcp/61u.key` first, then `fs:/card0/61u.key`
- References `lctsys/61s.dat` (likely stores hash/salt/state)
- Calls `IFILEMGR_OpenFile` → `IFILE_Read` → validation
- Function called early in boot via `OEM_LCTSystemCtl.c`

### Modem Side (AMSS.bin)
- Full WMS (Wireless Messaging Service) implementation
- QDIAG/QMI interfaces present
- SMS/OTA/FOTA support exists in modem firmware
- No 61u.key references in AMSS (key validation is ARM11-side only)

### Attack Vectors
1. **Statistical/Cryptanalytic** — Need spreadsheet data (≥30 IMEI→Key pairs)
2. **RE Validation** — Understand exact constraints, check for crypto verify
3. **TecToy Tool** — Find leaked internal keygen tool (C# like Aldebaran manager)
4. **Binary SMS** — If key cracked, inject via modem WMS → ARM9→ARM11 RPC → write key
